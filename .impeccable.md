## Design Context

### Users
Competitive Yu-Gi-Oh players in an organized community who draft and duel in the browser. Many also use the community's Discord server. They want fast, focused drafting with minimal friction — no missed timers, no hunting for the current state. Secondary audience: tournament organizers who manage events and need visibility into draft state.

### Brand Personality
Sharp, precise, game-tool — like a well-designed competitive gaming client. Fast and confident, not flashy. Three words: **competitive, focused, modern**.

### Aesthetic Direction
Dark-mode-first competitive UI. High-contrast card displays, crisp typography, minimal chrome. Think MTG Arena draft room meets clean dashboard — not a toy, not a collector showcase. Functional density over whitespace. Accent color from Yu-Gi-Oh brand (purple/gold) used sparingly for active states. Anti-reference: generic Discord bot dashboards, overly playful card-game UIs.

**Light/dark**: Dark mode primary, light mode supported.
**Must avoid**: Generic AI-dashboard aesthetic (cyan-on-dark, glassmorphism cards, rounded-rectangle grids).

### Design Principles
1. **Speed over ceremony** — Every extra click between seeing a pack and picking a card is a failure.
2. **Live state is truth** — Web sockets keep the board current; stale state is a bug.
3. **Draft-room immersion** — The drafting experience should feel like sitting at a table, not filling out a form.
4. **The web app is the lobby** — Players sign in with Clerk (email/password or Discord) and start drafts, tables and tournaments on the site. Discord is optional: an admin bot helps run the server, but the game never needs it.
5. **Competitive clarity** — Card images, pick order, timer, and your pool are always visible and unambiguous.
