Concept A

A. Sealed pack

The marketing hero, one click on. The brand pack stands beside the form, sealed while you are signed out. On success it tears open and the app loads.

Clerk flow mapping

Form zone is a plain single column, no frame of its own. Every step swaps in place under the same heading slot, so each Clerk step maps one to one. The pack never changes with the step, which keeps it independent of Clerk.

Fit with Clerk's prebuilt single card: Good

The form column is the prebuilt card (appearance variables, transparent card, our fonts). The pack, rings and backdrop are plain page elements outside it, so nothing fights the component. The tear needs to run after the redirect (a short "signing in" route on the app side) unless we go custom.

Motion

Entrance
Pack rises in (0.5s), form column fades up (0.34s). Steps cross-fade and rise 10px.
Signing
Pack trembles (2px, 0.14s loop) and its light pulses while the spinner row shows.
Success
The top strip tears off and flies away, rays and a burst fire, three card backs fan out, the logo mark drops into its slot. Hold about 1s, then redirect.
Reduced motion
Static torn pack, no tremble, no drift, no dust.

Honest trade-offs

  • Most on-brand: it is the same object people just saw on the marketing page.
  • Costs vertical space on phones: the small pack pushes the form down about 190px, and the invite screen scrolls.
  • The tear is a flourish. It only earns its place if the redirect gives it a second to play; on a slow redirect it is a delay.
  • Heaviest of the three (pack layers, rings, dust), though all of it is CSS transform and opacity.

Concept B

B. Card in the slot

The form is a card, seated in an oversize D that echoes the logo mark. Sign in is the front. Every later step is the back of the card, so each step flips it.

Clerk flow mapping

Each step is one card, front for the start step and back for everything after. One card is visible at a time, the other face is inert. The name bar and type line are decoration that follow the step.

Fit with Clerk's prebuilt single card: Poor

Clerk's appearance API restyles, it does not restructure. The name bar, type line, footer code and flip cannot be added around the prebuilt card. With the prebuilt card the honest version is a card frame around it with no flip, which loses most of the idea. A custom flow builds it as drawn.

Motion

Entrance
Card drops into the slot (0.62s, from 42px up and 3 degrees tilted).
Step change
Card flips 180 degrees (0.75s). Sign in is the front; the rest are the back.
Signing
The slot fills with gold light and the gem pulses. There is no separate success frame; the redirect follows.
Invite
The create-account card gets the gold rare border with a slow glint.
Reduced motion
No flip, no drop, no glint. Steps swap instantly.

Honest trade-offs

  • Most distinctive and tactile. Reads as a trading card, which fits the product.
  • A 0.75s flip on every step fights "speed over ceremony". It would need to be quick or only on the first step.
  • Create account is a very tall card (about 1,100px on desktop). Cards that change height break the card illusion.
  • Narrow card means longer error lines and tighter fields. Worst fit for Clerk's prebuilt card.

Concept C

C. Quiet table

Speed over ceremony. A near-empty dark field with faint duel-table zones in thin gold light, and one compact centred panel with the mark above it.

Clerk flow mapping

A single 400px panel; every step swaps inside it with the same heading, form and footer rhythm. This is the closest to what Clerk renders by default.

Fit with Clerk's prebuilt single card: Best

The panel is Clerk's card re-skinned with appearance variables. The table is a fixed background SVG behind it. No wrapper, no custom steps needed.

Motion

Entrance
Table lines fade in over about 1s in four groups; the panel rises 10px (0.3s).
Signing
One slot on the table glows gold and a card back drops into it (0.6s).
Success
Same frame as signing, then redirect. No separate frame.
Reduced motion
Lines and panel appear at once; the card back sits in the slot.

Honest trade-offs

  • Fastest to build, lowest risk, easiest to keep accessible. Nothing competes with the form.
  • Least memorable. It is a login screen first and a brand moment second.
  • The table is a generic grid at this opacity; it hints at a duel table but does not carry the pack or card motifs.
  • Smallest payoff on success, so the redirect has to be quick.

How the screens map to Clerk

Same in all three concepts. Step and error names are from memory of Clerk's docs and should be checked before the build.

ScreenClerk step
Sign inStart step: identifier (email) plus the Discord social connection. Identifier-first, so the password is asked on the next step.
Password, wrong passwordFirst factor, password. Wrong password is a field error on the same step. Pre-created members have no password, so the hint points them to Forgot password.
Email code, new passwordOne code step reused for sign-up verification, Forgot password (code, then new password) and the occasional new-device check. No passwordless sign-in.
Create account, username takenSign-up from the invite link (the invitation ticket carries and locks the email). Username, password, terms consent and the bot-check slot sit on the sign-up step. Username taken is a field error.
Not invited (sign in)Identifier not found, worded for the waitlist.
Not invited (sign up)Sign-up blocked in Waitlist mode.
BannedLocked or banned user, shown as a terminal step.
Service errorGlobal banner above the form; the form keeps its values.
Signing inSession created and redirecting. Short, 1s or less.

Prebuilt component or custom flow is still open. If Clerk Elements is considered for the custom route, check its current support status first.

Choices the brief left open

  • Continue with Discord is a neutral raised button with the white glyph, not Discord blue. Purple is kept for the one primary action on each step, so the two never compete.
  • The code step is one real text input drawn as six boxes (numeric, one-time-code autocomplete), so paste and keyboard work with no extra code. It has a Continue button as well as auto-submit, and a resend countdown.
  • The locked email on Create account is read-only with a lock icon, not disabled, so it stays readable.
  • The bot check is a dashed placeholder slot above Create account. Its real look comes from Clerk.
  • Banned copy is "This account can't sign in. If you think that's a mistake, reach out to the alpha team." There is no contact address or link yet; one is needed.
  • Sample email is sam@example.com. Typing "nope" as the email shows the not-invited state, and a password containing "wrong" shows the wrong-password state, so the live pages can be walked through.
  • Forgot password goes straight to the code step, then New password, then Signing in.
  • Screenshots at 1440 are the 900px viewport; Create account and its error are taller than that and are shot full page.
