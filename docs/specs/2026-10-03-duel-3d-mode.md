## 1. What 3D mode is

1. **"3D mode"** is a per-device display option. It is **off by default**. When it is on, a **1v1** duel (live, spectated or finished) uses the Solid Vision look:
   - a tilted obsidian table with a gold hairline frame, in the Nexus layout;
   - hands that are not tilted;
   - Card/Log inspector on the left and Deck Master docks on the right;
   - a phase bar with a sliding puck, and a whose-turn pill.

   See `C/index.html`, `C/styles.css`, `C/CONCEPT.md`, the shots in `C/shots/*.png` and `PICK`.
2. **Only the look changes.** Everything else is the same as the current 1v1 board (V1):
   - engine data, prompts, menus, aim and attack flow, log, gates, FX order and timings, sounds, hold and skip rules.
   - Rule: if a timing, motion or behaviour in the concept conflicts with V1, **V1 wins**. Concept section-14 timings are storyboard values only. Do not use them.
3. **Scope.**
   - 3D mode applies only when `!multi && !liveTable` in `DuelRoomView`. FFA3, FFA4, Tag and `?stage=legacy` keep their current shells.
   - Spectators and pop-out windows (`?window=1`) follow the same setting.
4. **Brand.** All visible text says "Duelists Kingdom", never "Yugidraft". The concept header says "Yugidraft". Replace it.
5. **Concept items that are NOT added:**
   - the dev strip (`--strip` = 0), keys 1-7, `?still`, `?demo`, `?nogl`;
   - the scripted STEP/UI/ENTER state machine;
   - the concept "skip moment" click/Space/Esc (V1 has none; see the owner questions);
   - the fake 15 s chain countdown;
   - the "Summon cut-in" option;
   - the concept-only menu letter hints (N, S, A). A worker may show them only if the hotkeys already exist in V1. They do not exist, so do not show them.

### 2.2 Tilt rules (CSS 3D)

These rules are mandatory. Each rule exists because an FX or measuring contract depends on it.

1. **One tilted node.** Only `.sv-plane` has a transform: `rotateX(var(--tilt))` with `transform-origin: 50% 80%`.
   - `perspective: var(--persp)` and `perspective-origin: 50% 50%` go on its parent `.sv-fieldwrap`.
   - Do not use `preserve-3d` anywhere. The plane's children flatten into it, which is what we want.
   - Do not put `will-change`, `overflow`, `opacity` or `filter` on `.sv-plane`. Its frame, glow and veil are painted with gradients, `box-shadow` and a `::after` child (`C/styles.css` 274-310).
2. **No transform on an ancestor of FX.** `.sv-root`, `.sv-stage` and `.sv-board` have no `transform`, `filter`, `perspective`, `contain: paint` or `will-change: transform`.
   - Reason: BattleFx (`D/battle-fx.module.css:30-36`) and MasterReturnFx (`D/master-return-fx.module.css:5-12`) use `position: fixed`, which needs a viewport containing block. See `D/battle-fx.tsx:801-804`.
   - Mobile sheets may use transforms on themselves only.
3. **Shake.** `[data-duel-field]` sits on the untilted `SolidField` root. `Fx3dEngine.applyShake` (`D/fx3d/engine.ts:31, 301`) writes inline `transform` there. Never put the tilt on that node.
4. **Untilted parts.** Hands, plates, Deck Master chips, prompts, menus and every overlay are outside `.sv-plane`.
5. **Values.**
   - Desktop: `--tilt: 15deg`, `--persp: 1400px`.
   - Narrow (`max-width: 900px`, the same as `useIsNarrow()` / `NARROW_QUERY` in `D/side-panel.tsx`): `--tilt: 8deg`, `--persp: 760px`.
   - Flat view: `.sv-root[data-view="flat"]` sets `--tilt: 0deg`.
   - Use the app breakpoint of **900px**. Do not use the concept's 760px.
6. **Tilt transition.**
   - `transform .55s cubic-bezier(.16,1,.3,1)` and `--light-y .9s` (with `@property --light-y`). This is compositor-only.
   - Under `data-reduced="true"`, both transitions are `none`.
   - CSS transitions are ignored by `usePromptReveal`. This is correct, because the tilt is not an FX.
7. **Measuring.**
   - All code measures with `getBoundingClientRect()`. In the tilted plane this returns the projected bounding box, and that is what FX and overlays use.
   - Never use `offsetLeft`, `offsetTop` or `offsetX` inside the plane, except for the plane-local SVG (attack path), which is laid out in plane coordinates.
8. **Crispness.**
   - The first build uses a plain `rotateX` with no supersample.
   - The integration worker checks for text blur on the ATK/DEF plates and pile labels with a 2x zoomed screenshot.
   - If they are blurry, apply the n-player texel trick to an inner `.sv-planeInner`: `zoom: var(--ss); scale: calc(1/var(--ss))` with `--ss` = 2 on desktop and 1.5 on `(pointer: coarse)`. See `D/table/table-stage.module.css` `.wstage`.
   - Do not apply it to `.sv-plane` itself.
   - Lesson from 4f4c2b05: a permanent `preserve-3d` together with perspective causes the blur.

### 2.3 FX anchoring on the tilted table

- **V1 FX are reused without change.** They find targets through DOM hooks and screen rects, so they land on tilted zones. They are siblings of `SolidField` inside `.sv-board`, so they stay flat.
- **Hooks that must stay on SolidField** (the same elements and values as `DuelField`):
  - `[data-zones]`, `data-kind`, `data-legal`, `data-selected`, `data-occupied`, `data-equip`, `data-defense`, `data-side`, `data-disabled`;
  - `[data-hand-seat]`, `[data-hand-id]`, `[data-hand-card]`, `[data-hand-size-probe]`, `--hn`, `--hn1`, `--i`;
  - `[data-lp-seat]`, `[data-card-art]`, `[data-pile-count]`, `[data-master-dock]`;
  - `[data-field-seat]`, `data-turn` and `data-priority` on each half wrapper;
  - `[data-duel-field]`, `data-battle`, `data-reduced-motion`, `data-master-rule`.
- **Half wrappers.**
  - The Nexus grid has no half `<div>` boxes, because the piles share rows with the zones.
  - Put `data-field-seat` on two `display: contents` wrappers, one per seat. Each wrapper holds that seat's zones in DOM order. Grid placement uses explicit `grid-row` and `grid-column`.
  - `display: contents` keeps attribute queries working. It has no box, and no code reads its rect. Check this: grep for `[data-field-seat]` rect reads. If any exist, use a zero-size `position: absolute` marker instead.
- **Projected boxes.** At 15deg, the bounding box of a far-row card is about 3-5% shorter and its centre moves up by a few px. This is acceptable.
  - Acceptance: an FX centre lands within 6px of the zone's rect centre, and the ghost size is within 8% of the rect, at 1440x900. Test with 3.6.
- **fx3d.** `D/fx3d/engine.ts` stays an orthographic camera (1 unit = 1 CSS px, `PIXEL_RATIO_CAP` 1.5, on-demand loop, adaptive quality). Add these:
  - `setTableTilt(deg: number)`: ground-plane parts (summon circles, rings, discs) rotate by `-deg` about X inside a group at the zone centre, so they lie on the table, like `tableGroup()` in `C/projection.js`. Default is 0, so V1 output is unchanged.
  - `setPalette("v1" | "solid")`: solid uses gold `#c8a55f` / `#e8cf94`, purple `#8f76f2` / `#b8a8ff`, and loss red `#f27a6b`. It never changes durations, the order of effects or the routes.
  - SolidRoom sets both values from its state. Tilt is 0 under the Flat view and on narrow screens when `--tilt` is 0. Read the computed value with `parseFloat(getComputedStyle(plane).getPropertyValue("--tilt"))`.
  - Do **not** add the concept's separate `PerspectiveCamera` `ProjectionCanvas`. One WebGL context only, the existing one.
- **No new FX moments.** The concept's hologram summon, attack arc and shatter map onto V1's heavy/typed summon, `BattleFx` 3D route and `DestroyFx` shards. They are restyled (palette, plane alignment) only. Their timing is not changed.
- **Tilt/Flat during FX.** The header Tilt/Flat button and the 3D mode switch apply only when `boardQuietNow(boardRef.current)` (`D/result-reveal.ts:77`) is true. Otherwise they wait: poll every 100 ms through `duelFxClock.setInterval`, up to 3000 ms, then apply anyway. A change closes the card menu and the hover info (`closeMenu()`, `setHover(null)`). After `transitionend` on `.sv-plane`, dispatch `window.dispatchEvent(new Event("resize"))` so `placeSelectBar` and the anchored positions re-measure.

### 2.4 Performance budget

- **No new continuous rAF loop.** The fx3d loop is already on demand. The tilt is static CSS. Clocks keep V1 behaviour.
- **No layout thrash.** No new code reads layout in render. Any new measure (plane SVG, tilt read) runs in one rAF, with reads before writes (the pattern in `D/live-flight.ts`).
- **Tilt toggle runs at 60 fps** (transform only). Hover and legal states change only `box-shadow` and `translate` on children.
- **Zero cost when 3D mode is off.**
  - `S/solid-room.tsx` (and everything it imports: `SolidField`, the solid CSS, the Barlow fonts) loads through `next/dynamic(() => import("./solid/solid-room"))`.
  - Classic users load only `D/board-view.ts`, `D/skin.tsx` (under 2 KB) and the settings row.
  - When the store says `3d`, `DuelRoomView` starts `void import("./solid/solid-room")` in a mount effect, before the room data arrives, so the chunk is ready.
- **Fonts.** Barlow Condensed 300/400/500 and Barlow Semi Condensed 300/400/500/600 come through `next/font/google` in `S/fonts.ts`, which only the solid chunk imports. CSS vars: `--sv-font` and `--sv-font-num`.
- **Card art** is the existing same-origin `cardArtUrl()` (`D/constants.ts`), so there is no CORS issue for WebGL (`D/fx3d/art.ts`).

### 2.7 Reduced motion

`preferences.reducedMotion` (Motion setting plus `prefers-reduced-motion`) does the following:

- sets `data-reduced="true"` on `.sv-root`;
- turns off the tilt and light transitions, the puck slide, the hand lift transition and the sheet slide (all `transition: none`; no `0.01ms` hacks needed);
- leaves the tilt angle itself unchanged. The tilt is a layout, not motion;
- keeps fx3d off, as it is today (`use-fx3d.ts` only loads when `!reducedMotion`);
- keeps all V1 `reduced*` timings as they are.

If WebGL is not available (`webglSupported()` in `D/fx3d/loader.ts`), the V1 DOM fallbacks run, as they do today. Nothing new is needed.

## 3. Foundation (one worker, alone, first)

### 3.1 Setting store: `D/board-view.ts` (new)

- **localStorage key:** `"yugidraft.duelBoardView.v1"`, value `{ v: 1, mode: "classic" | "3d", tilt: "tilt" | "flat" }`.
  - Default: `{ mode: "classic", tilt: "tilt" }`. Bad or missing data gives the default.
  - Use a separate key, NOT a new field in `yugidraft.duelPreferences.v1`. `savePrefs()` in `D/preferences.ts` rewrites the whole object, so a new field there would be lost.
- **API:**
  - `readBoardView()` and `writeBoardView(next)`. Writes notify in-tab listeners. The `storage` event covers other tabs and pop-outs.
  - `useBoardView(override?)` returns `{ mode, tilt, setMode, setTilt }`. It uses `useSyncExternalStore`, and the server snapshot is the default.
  - `override` comes from the page query `?view=3d|classic`. It wins and is not saved.
- **Why there is no flash, and no cookie.** `DuelRoomView` gets its room data from SWR on the client (`getDuelRoom`, with no server fallback data), so the board never renders in SSR HTML. On client navigation, `useSyncExternalStore` reads the snapshot synchronously. The board therefore never appears in the wrong look. A cookie would add server work and gain nothing.
- **Unit test:** `W/tests/duel-board-view.test.ts`. Cover the default, a bad payload, round trip, override precedence, and that the `storage` event notifies.

### 3.2 Skin context: `D/skin.tsx` (new)

```ts
export type DuelSkinSlot = "field" | "station" | "lp" | "feedback" | "side" | "inspector" | "history"
  | "menu" | "pile" | "prompt" | "tray" | "precheck" | "chain" | "battle";
export type DuelSkin = Partial<Record<DuelSkinSlot, Readonly<Record<string, string>>>>;
export const DuelSkinProvider: React.Provider<DuelSkin | null>;
/** Returns base unchanged when no provider/slot; else {k: `${base[k]} ${skin[k] ?? ""}`}, memoised per (base, skinSlot). */
export function useSkinStyles<T extends Readonly<Record<string, string>>>(base: T, slot: DuelSkinSlot): T;
```

- **Pattern in a skinned file:**
  1. `import baseStyles from "./x.module.css"`.
  2. In each function component that uses classes, add `const styles = useSkinStyles(baseStyles, "slot")`.
  3. Helper functions that are not components receive `styles` as an argument.
- The classic look is byte-identical: there is no provider, so it returns `base`.
- **Portals.** Context passes through React portals. `CardActionMenu` and others are rendered under `SolidRoom`'s provider, so they get the skin even though they portal to `body`.
- **Unit test:** `W/tests/duel-skin.test.tsx`. Cover no-provider identity, merge, and memo identity.

## 7. Risks

- **Phone zones** are about 50px at 390. Taps rely on the V1 anchored menu. The `data-zones` hit area is the whole zone cell (`--s`), not only the card.
- **`position: fixed` FX layers break if anyone adds a transform or filter to `.sv-root`, `.sv-stage` or `.sv-board`.** Add a short comment in `solid-room.module.css`.
- **Shared field slot.** Three CSS files feed one skin slot. Duplicate keys give unclear precedence. The test in 3.5 guards this.
- **`display: contents` half wrappers.** If any code reads the rect of `[data-field-seat]`, use the fallback marker (2.3).
- **The opening deal** depends on `[data-hand-seat]` geometry and `data-hand-size-probe`. W2 must keep the probe element and its size rules.
- **Refactor risk in `DuelRoomView`.** The foundation must keep the classic DOM identical. Review it with a DOM snapshot of a fixture room before and after.
- **MR3 Pendulum zones** have no separate cells in the Nexus grid (see the owner questions).
- **Projected boxes.** `getBoundingClientRect` on the tilted plane gives the projected box. Far-row ghosts can be a few px off. The tolerances in 2.3 and the W7 check guard this.
- **Text blur under the tilt.** The fix is the `--ss` trick on an inner node only (2.2.8). Never use a permanent `preserve-3d` (lesson from 4f4c2b05).
- **Prompt reveal ignores CSS animations.** `usePromptReveal` waits only on script Web Animations. A new CSS keyframe that must hold a prompt will not hold it. Do not add motion that must gate a prompt.
- **Remount on toggle.** A switch between classic and 3D mounts a new field tree. Running FX are lost. The quiet gate (2.3) limits this.
- **Container query leakage.** The V1 `@container (max-width: 640px)` phone rules must not match inside SolidField. `container-type: normal` on the Solid root prevents it.
- **Font loading in Docker builds.** `next/font/google` downloads Barlow at build time. If the build has no network, the build fails. Check the Docker build once in W9.
- **Concept brand text.** The concept says "Yugidraft". Visible text must be "Duelists Kingdom".
