# Remote match flow

Backend contract for `feat/remote-match-ui`. Import from `@yugidraft/shared/remote`.
`match-contract.ts` exports the match types, action schemas/names and timer constants.

- Create a room with `bestOf: 1 | 3`. Default: 1 for solo/test tables (one human), otherwise 3 for two seats and 1 for larger tables. An explicit `bestOf` overrides this default. The host can change `bestOf` in the lobby through `POST /api/remote/:slug/format { bestOf: 1 | 3 }` (other format fields are optional). The room also exposes `bestOf`; the room controller exposes `setBestOf(bestOf)` for the lobby settings control. Changes clear human lobby Ready marks. Physical players can ready without an attached deck; attached decks must pass validation.
- `state.match = { bestOf, games, phase, siding?, winnerSeat?, pendingResult?, firstChooser?, firstSeat? }`. `phase` is `duel | result | siding | done`. Each game is `{ n, winnerSeat: number | null, reason: 'lp' | 'concede' | 'declared' | 'timeout', endedAt }`. Times are Unix milliseconds from the server.
- `state.ended` and `state.winnerSeat` describe the current game. Room `status` stays `active` through results/siding and becomes `ended` when the match is done. Two wins decide BO3; draws add a game without a win. BO1 ends after one game, including a draw (`match.winnerSeat: null`). Larger tables use individual seats and elimination, as before.
- LP elimination or `player.concede` ends the game when at most one seat remains. A nonfinal game enters `result`. A decided match enters `done`; the last game still supplies the result screen. `match.continue` opens siding from `result`.

Send actions to the existing `POST /api/remote/:slug/actions` as `{ baseSeq, action: { type, actorSeat, idempotencyKey, ...payload } }`.

| Action | Payload / effect |
| --- | --- |
| `player.concede` | Concede your own seat. No confirmation. |
| `match.declare` | `{ winnerSeat: number | null }`. A living seat proposes a win or draw. The proposer confirms automatically. An eliminated seat cannot declare or be proposed as winner. |
| `match.confirm` | `{ declarationId, accept: boolean }`. Each other living seat confirms once. A rejection clears the proposal. The game ends after all living seats confirm; eliminated seats cannot confirm or reject and are never required. |
| `match.continue` | Open siding. Any seated player, including the loser, can continue. |
| `match.first` | `{ seatGoesFirst }`. Only `match.firstChooser` can choose during siding. |
| `side.ready`, `side.unready` | `{ seat }`. Only that seat's actor can change its Ready state. Available in solo BO3 too: the human's `side.ready` also readies owned bot seats. The solo host can act as a bot seat, including the first-player chooser. |
| `side.swap` | `{ deckChanges: { main: number[], extra: number[], side: number[] } }`. Replace your attached deck's sections; keep every card and each section's size. Main 40–60; Extra and Side at most 15. Deck Master stays fixed. A save clears your Ready state. The saved deck library stays unchanged. |
| `side.timeout` | No payload. An idempotent clock check, never a game loss. The server supplies time; its periodic sweep is authoritative. Early, duplicate and late checks return the current room successfully without an event, sequence increment or idle-clock refresh when nothing is due, including after siding or match end. A due check may advance state even with a stale `baseSeq`; normal actions still require the current sequence. |

`pendingResult = { id, winnerSeat, confirmed: number[] }`. Confirm the current ID; stale/duplicate confirmations are rejected. LP elimination or a concession clears a pending declaration.

`siding = { deadline, seatDeadlines: Record<number, number>, firstChoiceDeadline?: number, ready: number[], extendedFor: number[] }`. Physical-only seats get 180 seconds. Only seats with an attached deck list get 300 seconds and appear in `extendedFor`. `seatDeadlines[seat]` exposes each seat's actual cutoff; `deadline` is their maximum. Older stored snapshots without `seatDeadlines` are normalized when read; `remoteSideDeadline(siding, seat)` also supports that legacy shape. Expired seats become Ready and cannot edit their decks or readiness. A physical seat expiring in a mixed room does not start the game: show its remaining wait using the final `deadline`, never "starts now" based on its own cutoff. The chooser can pick until the final deadline even after its own siding time expires, subject to the shorter choice timer below.

The next game starts when all seats are Ready and the first-player choice is set, or when the final deadline passes. If all seats are Ready without a choice, the server sets `siding.firstChoiceDeadline` to 20 seconds later, capped by the final deadline. When it expires, the previous loser goes first automatically. Going unready or saving a deck before that cutoff clears the choice timer; it starts afresh when everyone is Ready again. Readiness, swaps and first-player choices cannot change after that choice cutoff. After a draw, the previous first player goes first. Larger-table BO3 uses the seat after the winner as chooser and timeout default. Schedule client clock checks against the next pending seat deadline or `firstChoiceDeadline`, as well as the final deadline. The server sweep runs every 30 seconds and applies elapsed deadlines even if all clients disconnect; client `side.timeout` requests can apply them sooner. Client time never decides a transition.

The next game resets LP to the room's configured starting LP, all field/pile/hand twins, eliminations, turn/phase, pending attacks, recognition/effect tracking and live deck warnings. It keeps deck registrations, room rules and the match record. Declarations, confirmations and rejections preserve every player's undo history. Undo can correct the current game before siding, including LP/concession or declared results. Entering siding clears history; Undo cannot cross games. Match state uses normal room snapshots, private projection, event replay and WebSocket broadcasts. New actions and sweep events persist `matchFlowVersion: 1` in server event context; historical events without it retain the original declaration participants and choice timing on replay. Solo bot readiness is also recorded in event context for deterministic replay. Deck swap contents remain private to their owner.

Table lists select metadata and `match.bestOf` directly from stored JSON, without loading board/undo state or replaying events. Room views read full state once. The 30-second sweep filters siding rooms in SQL and reads only their match fields to check deadlines; only due transitions load full state. Idle warnings and closures use metadata only.
