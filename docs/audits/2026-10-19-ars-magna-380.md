# Issue 380: Ars Magna hand search

The server loses the lowest setcode when it reads some 64-bit SQLite values as JavaScript numbers. This defect prevents Ars Magna of Purification and Corruption (`62368221`) from searching Ars Magna - "Citrinitas" (`37279096`). Citrinitas is a Continuous Spell, type `0x20002`. It is a valid target.

## Cause and fix

`src/cards.ts` used `SELECT * FROM datas` without safe integer mode. For Citrinitas:

| Stage | Packed setcode | Lowest 16 bits |
| --- | --- | --- |
| SQLite row | `0x1d001cb01c701dd` | `0x1dd` (Ars Magna) |
| Read as Number, then converted to BigInt | `0x1d001cb01c701e0` | `0x1e0` |
| Read with `.safeIntegers()` | `0x1d001cb01c701dd` | `0x1dd` |

The exact SQLite value is `130606360613552605`. JavaScript Number cannot hold this integer exactly. Converting the rounded number to BigInt does not restore its lost bits. The other three codes, `0x1c7`, `0x1cb`, and `0x1d0`, survive this specific rounding. This explains why the error depends on the code's position in the packed field.

The fix enables `.safeIntegers()` on the `datas` statement. The existing converters keep small fields as numbers and preserve setcodes and race as BigInt. Both engine adapters use this shared reader. No card script, core pin, or card database change is required.

The deck editor uses setcodes from the shared reader for its archetype filter. The shared reader fix also repairs this filter for these five cards.

## Domain and client checks

The Domain admission reader in `src/deck-legality.ts` already uses `defaultSafeIntegers(true)`. Its setcode read is exact. Admission checks can reject a deck, but do not remove one hand action from an active duel. The Domain Lua overlay handles the Deck Master Zone and summon procedures. No card-specific override changes this search. The real Domain and multi-domain results confirm that the hand search works with that overlay after the reader fix.

The client integration checks use real engine views in 1v1, FFA3, and FFA4. Both the classic hand and HUD hand show the usable state. Clicking the card opens an action menu with the engine's activation. Clicking that menu item sends its option ID to the real engine and pays the banish cost. No client rule change is needed. These are DOM integration checks; they do not reproduce the original mobile Edge session or measure its screen layout.

The public report came from `/decks` and has no format, board, or replay. It cannot prove the player's exact prior effects or once-per-turn use. The reproduced reader defect explains the reported symptom without either condition.
